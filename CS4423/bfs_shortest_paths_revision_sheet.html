Rapid refresher

Core ruleExam distinction
Use a FIFO queue. On first discovery set d[v]=d[u]+1 and pred[v]=u. In an unweighted graph BFS gives minimum edge count.A predecessor tree records one shortest path; multiple predecessors can yield multiple shortest paths.

Medium/hard adapted practice

(a) Run BFS from s and give distances and a shortest path to t. [8 marks]

Question demand: apply the definition/calculation with working. Quickest route: Show queue/levels in the specified neighbour order; stop only when the requested condition permits it; backtrack pred from t.

Mark-aware answer: Set d(s)=0. Each first discovery crosses one edge from level i to i+1, so no later route can be shorter. Backtracking t,pred(t),... ,s and reversing gives a shortest s-t path.

Trap: Using a stack accidentally gives DFS, not BFS.

(b) Give BFS pseudocode and its time complexity for an adjacency-list graph. [6 marks]

Question demand: Initialise all vertices once; enqueue/dequeue each vertex once; scan each adjacency list once. Quickest route: Initialise all vertices once; enqueue/dequeue each vertex once; scan each adjacency list once.

Mark-aware answer: Set all distances to infinity, set d[s]=0, enqueue s; while Q nonempty dequeue u and for each undiscovered neighbour v set d[v]=d[u]+1, pred[v]=u, enqueue v. This costs O(|V|+|E|).

Trap: Mark on discovery, not on dequeue, to avoid duplicate queue entries.

(c) Explain why BFS does not solve weighted shortest paths in general. [4 marks]

Question demand: Give a two-route counterexample by hop count versus weight. Quickest route: Give a two-route counterexample by hop count versus weight.

Mark-aware answer: BFS minimises number of edges. A one-edge route of weight 100 is chosen before a two-edge route of weights 1 and 1, although the latter is cheaper. Use Dijkstra for nonnegative weighted edges.

Trap: Do not call every graph distance unweighted without checking the problem.
