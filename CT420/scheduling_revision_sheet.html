CT420 Revision

Scheduling and Schedulability

Turn periodic task data into a clear feasibility argument.

Rapid exam refresher

  • For task τi record C,T,D; U=ΣC/T. RM gives shorter T higher fixed priority; EDF runs earliest absolute deadline.
  • On an ideal pre-emptive single CPU with D=T, EDF U≤1 is exact. The RM utilisation bound is sufficient only.
  • Fixed-priority response time: Rᵢ=Cᵢ+Bᵢ+Σ⌈Rᵢ/Tⱼ⌉Cⱼ; iterate until fixed point or R>D.
  • A cyclic executive uses a repeatable frame table; releases, deadlines, frame budget and overrun handling all matter.

Paper evidence and scope

CE/RM/EDF/schedulability recur in local papers 2017/18, 2018/19 and 2021/22–2024/25. Questions below are adapted, not copied.

Medium practice — 15 marks

τ1=(1,4), τ2=(2,5), τ3=(4,20), D=T. (a) [5] assign RM priorities/calculate U. (b) [5] apply the RM bound. (c) [5] calculate R3.

Answer for every part

(a) Demand, quickest route, worked answer, trap

Route: sort by T, then sum C/T. Answer: τ1>τ2>τ3; U=1/4+2/5+4/20=.85. Trap: sorting by C instead of period.

(b)

Route: quote then qualify the sufficient bound. Answer: 3(2^(1/3)−1)≈.779; .85>.779 is inconclusive, not a failure proof. Trap: treating the bound as necessary.

(c)

Route: start R=4; add higher-priority interference. Answer: 4→7→10→11→13→14→14, so R3=14≤20. Trap: omitting ceiling functions.

Hard practice — 15 marks

A cyclic executive must run A=(C=1,T=D=4), B=(C=1,T=D=8), C=(C=2,T=D=8). Use a 4-unit frame and hyperperiod 8. (a) [5] construct a valid two-frame table. (b) [5] add concrete overrun detection for C. (c) [5] compare the result with EDF if C takes 3 units in its first job.

Answer for every part

(a) Demand, quickest route, worked mark-aware answer, trap

Demand / route: list releases in [0,8), allocate frame capacity, then check every D. Answer: at t=0 release A0,B0,C0; frame [0,4): A0 0–1, B0 1–2, C0 2–4. At t=4 release A1; frame [4,8): A1 4–5 and 3 units idle. A0/B0/C0 finish by D=4/8/8; A1 finishes by D=8. This earns 2 marks for releases/table, 2 for capacity/completions, 1 for deadline conclusion. Trap: scheduling B or C again at t=4 although T=8.

(b) Demand, quickest route, worked mark-aware answer, trap

Demand / route: compare measured execution with C’s 2-unit budget at the frame boundary. Answer: read a monotonic clock before C; if elapsed>2, set an overrun flag, log task/job/frame, notify watchdog and enter defined policy (skip non-critical work or safe state). Do not simply continue into [4,8), because that hides a schedule violation. Credit: timing check 2, detection/report 2, safe response 1. Trap: using wall-clock time that can jump after synchronisation.

(c) Demand, quickest route, worked mark-aware answer, trap

Demand / route: recompute first-frame demand under EDF and compare deadlines. Answer: if C0=3, work released at 0 is A0+B0+C0=5>4; EDF runs A0 first (D4), then B0/C0 both D8, but only 3 units remain before t=4. It can finish all B0/C0 by t=5, still before D=8, while CE’s fixed frame budget reports C’s overrun. EDF is feasible over [0,8): demand A0+A1+B0+C0=1+1+1+3=6≤8. Credit: EDF ordering 2, demand/deadline calculation 2, contrast 1. Trap: claiming any CE budget overrun is automatically an EDF deadline miss.
