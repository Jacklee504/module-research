Time Synchronisation

Calculate offset and delay, then explain the protocol mechanism that makes the result believable.

Rapid exam refresher

  • Offset difference, skew rate, accuracy reference, stability consistency.
  • NTP vs PTP.
  • offset/delay formulas assume symmetry.

Purpose, scope and examiner demand

Distributed devices need a shared notion of time for ordering, control and measurement. NTP targets robust network synchronisation; PTP targets high accuracy on suitable networks.

Exam focus by part

  • Offset difference, skew rate, accuracy reference, stability consistency.
  • NTP vs PTP.
  • offset/delay formulas assume symmetry.

Question-demand diagnosis and answer plan

  1. Draw the four timestamps in order: client send t1, server receive t2, server send t3, client receive t4.
  2. Use the supplied direction convention and show substitutions.
  3. Discuss asymmetry, timestamp quality, and hierarchy rather than treating the number as exact.
  4. For PTP, name grandmaster selection and the relevant clock type/mechanism.

Question-type cues

  • Application cue: t1=100,t2=112,t3=120,t4=134ms.
  • Analysis cue: Choose PTP versus NTP for precise LAN.

Definitions, notation and discriminating comparisons

  • Offset: difference between clocks; skew/drift: rate at which their difference changes.
  • NTP round-trip delay: delta=(t4-t1)-(t3-t2). Offset (server minus client convention): theta=((t2-t1)+(t3-t4))/2.
  • PTP grandmaster: selected best clock; BMCA: Best Master Clock Algorithm.
  • Boundary clock: synchronises one port and serves others; transparent clock: corrects residence time. Hardware timestamps reduce uncertainty.

Step-by-step methods and solution routes

Let t1=100, t2=112, t3=114, t4=130 ms. Delta=(130-100)-(114-112)=28 ms. Theta=((112-100)+(114-130))/2=-2 ms: by this convention the server is 2 ms behind the client. The calculation assumes equal forward/reverse delay; asymmetric paths bias offset.

Worked examples and method extensions

Question

Why might a factory use PTP with transparent clocks rather than ordinary software-timestamp NTP?

Model answer

PTP can use hardware timestamps close to the network interface, reducing variable software delay. Transparent switches measure/correct their residence time, so switching delay contributes less uncertainty. A BMCA elects a grandmaster and supports a hierarchy. NTP is robust and widely useful, but its typical network/software timing uncertainty may be unsuitable for tightly coordinated factory actions.
