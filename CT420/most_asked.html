Real-Time Systems – Most Asked Exam Questions

Recurring question families from the seven local papers, with marks, paper structure, and reusable answer frames.

How To Use This Document

This is a question-family guide, not a prediction of an exact question slot. The 2024/25 and 2025/26 papers both use two sections: answer two of three 15-mark questions in Section A and two of three 15-mark questions in Section B. The 2023/24 paper instead makes Question 1 and Question 4 compulsory; 2022/23 and 2021/22 require Question 1 plus two others; the 2017/18 and 2018/19 structures differ again.

  1. Start with the latest two papers because their structure and staff pairing match.
  2. Attempt the original listed question before reading the answer frame.
  3. Use the frame to check for a definition, mechanism or calculation, evidence or diagram, and a limitation where the command word needs one.
  4. Use the linked topic guides for worked methods, then turn only the short retrieval prompts into flashcards.

Most Repeated Question Families

Frequency is based on direct examination across the seven available papers. A recent three-paper run can matter more than a higher-frequency historical topic when deciding the final revision order.

Priority 1 – Time Synchronisation, Clocks, NTP And PTP

Frequency: 7/7 papers directly. It is also the strongest current Section A family.

Appears as:

  • 2025/26 – Q1(a) lunar localisation stack [5]; Q1(b) PTP hardware timestamps, transparent clocks and P2P delay [6]; Q1(c) Berkeley algorithm [4].
  • 2024/25 – Q1(a) accuracy, stability, offset and skew [5]; Q1(b) clock handler with skew compensation [5]; Q1(c) Berkeley [5]. Q2(b) PTP mechanisms [5].
  • 2023/24 – Q3(b) PTP master, transparent clock and slave, including correction data and an offset or delay calculation [5].
  • 2022/23 – Q3(a) Berkeley and UTC suitability [5]; Q4(b) PTP hardware timing, transparent clocks and P2P calculation [7].
  • 2021/22 – Q1 PTP architecture, E2E/P2P, boundary and transparent clocks, BMCA redundancy, and NTP backup [20].
  • 2018/19 and 2017/18 – NTP workings, round-trip delay, offset, filters, NTP-versus-PTP comparison, and ntpq interpretation.

Consolidated most-asked question:

For a distributed system requiring accurate clocks, choose and explain an NTP, PTP, or Berkeley design. Show the relevant messages and timestamps or calculation, then state the assumption or limitation that bounds the claimed accuracy.

Reusable answer frame: Define the timing need and required accuracy. For NTP, label t1 to t4, calculate RTD = (t4 − t1) − (t3 − t2) and state the offset convention. For PTP, draw grandmaster → boundary or transparent clock → slave; explain hardware timestamping, Sync/Follow_Up, delay messages, residence-time correction, and BMCA where relevant. State that asymmetric paths, software delay, bad clock selection, or a missing external reference can bias the result. Berkeley averages internal clocks; it does not by itself supply UTC.

Priority 2 – Cyclic Executives, RM, EDF And Schedulability

Frequency: 7/7 papers directly.

Appears as:

  • 2025/26 – Q2(c) RM analysis and schedule over [0, 400] [5]; Q3(a) cyclic-executive pseudo-code that detects and counts overruns [5].
  • 2024/25 – Q2(c) RM analysis and schedule [5]; Q3(a) cyclic executive with overrun detection [5].
  • 2023/24 – compulsory Q1: construct CE, RM and EDF schedules, compare them, then implement the CE and detect asynchronous-interrupt overruns [20].
  • 2022/23 – Q1(c) construct an EDF-feasible but not RM-feasible four-task set, validate with utilisation, timeline and RM analysis [7]; Q3(c) CE and interrupt mitigation [6].
  • 2021/22 and 2018/19 – CE code and timeline, available interrupt time, plus WCET / longest-path reasoning.
  • 2017/18 – Q6 RM versus EDF and a proved EDF-feasible but not RM-feasible design [25].

Consolidated most-asked question:

Given periodic tasks, construct or analyse the stated CE, RM, or EDF schedule. Show the timeline and all arithmetic, then explain what a pass or failure proves under the stated assumptions.

Reusable answer frame: Tabulate each task’s execution time C, period T, deadline D, and priority. Calculate U = Σ(Ci/Ti). For RM, order by shortest period and use the requested bound or response-time recurrence; a failed sufficient bound is inconclusive, not automatic failure. For EDF with D = T on one ideal processor, use U ≤ 1. Draw the requested interval or hyperperiod. For CE pseudo-code, show the frame loop, task calls, elapsed-time check, and an overrun counter or recovery action. State assumptions about pre-emption, blocking, overhead, releases, and deadlines.

Priority 3 – POSIX Real-Time Support, Concurrency And Priority Protocols

Frequency: 7/7 papers directly; the exact API focus varies, but the systems reasoning is persistent.

Appears as:

  • 2025/26 – Q2(a) select four POSIX-style RTOS capabilities [6]; Q3(b) control a critical region with a mutex / binary semaphore [5]; Q3(c) memory locking and the seven-state model [5].
  • 2024/25 – Q3(b) benefits of Priority Inheritance with a diagram [5]; Q3(c) memory locking and consequences of not using it [5].
  • 2023/24 – Q3(a) CE overrun detection and Q3(b) Priority Inheritance [5 each].
  • 2022/23 and 2021/22 – Priority Ceiling preventing deadlock with shared resources; POSIX.4 signals and sigqueue.
  • 2018/19 and 2017/18 – semaphore deadlock, memory locking, POSIX timers / sleep / signals, and priority protocols.

Consolidated most-asked question:

Explain a real-time resource-management failure using a timeline or process model, then show the POSIX mechanism or priority protocol that bounds, prevents, or exposes it.

Reusable answer frame: Identify the high-, medium-, and low-priority tasks and the shared resource. Draw the causal timeline. For priority inversion, explain how a medium task delays the low-priority lock holder while the high-priority task waits; Priority Inheritance temporarily boosts the holder. For a Priority Ceiling answer, show how the unsafe second acquisition is blocked before circular wait. For memory locking, connect paging to a state transition and unbounded delay; explain mlock/mlockall in pseudo-code and the risk of locking too much memory. Include a trade-off: bounded blocking is not no blocking, and protocols do not remove the need for short critical sections.

Priority 4 – QUIC, HTTP/2, HTTP/3, Congestion And Protocol Analysis

Frequency: 3/7 directly, but it occupies the recent Section B direction in all three latest papers and aligns with the current module scope.

Appears as:

  • 2025/26 – Q4 TCP head-of-line blocking and QUIC [7], ABR streaming [8]; Q5 qLog/qViz [4], congestion-control fairness [5], QUIC encryption [6]; Q6 cloud gaming, connection migration, congestion control and loss recovery [15].
  • 2024/25 – Q4 HTTP/1 → HTTP/2 and three HTTP/2 features [7], QUIC-versus-TCP establishment and latency [8]; Q5 Wireshark, qLog, qViz and QUIC congestion control [15].
  • 2023/24 – compulsory Q4 QUIC establishment, multiplexing / TCP head-of-line blocking, and congestion control [20]; Q5 Wireshark limitations, qLog/qViz, and resource waterfalls [10].

Consolidated most-asked question:

Connect a QUIC or HTTP design feature to a concrete latency, loss, multiplexing, monitoring, or congestion symptom in a soft real-time system. State both the improvement and what it does not solve.

Reusable answer frame: Name the stack correctly: HTTP/2 multiplexes over one ordered TCP byte stream; HTTP/3 uses QUIC over UDP. Explain that TCP loss can create transport-level head-of-line blocking for unrelated HTTP/2 streams, whereas QUIC independently orders streams. Draw the connection-establishment round trips if asked. Then cover the relevant mechanism: encrypted transport metadata, congestion control, loss recovery, connection migration, qLog endpoint events, qViz visualisation, or Wireshark’s limits with encrypted traffic. Finish with the limitation: QUIC does not eliminate packet loss, RTT, server work, shared congestion, or monitoring requirements.

Priority 5 – Soft Real-Time, QoS, VoIP, Streaming And Cloud Gaming

Frequency: 4/7 directly, with a strong current recurrence in 2024/25 and 2025/26.

Appears as:

  • 2025/26 – Q4(b) adaptive-bitrate streaming, estimation, quality–latency trade-offs, and why ABR is insufficient for interactive use [8]; Q6 cloud-gaming end-to-end delay [5].
  • 2024/25 – Q4(b) latency in soft real-time systems [8]; Q6 QoS versus perceived / intrinsic QoS, jitter buffers, and cloud-gaming response delay [15].
  • 2023/24 – compulsory Q4 asks about latency in soft real-time systems [7].
  • 2018/19 and 2017/18 – VoIP FEC, mouth-to-ear delay, DASH, codec range, RTP/RTCP, QoS and QoE.

Consolidated most-asked question:

For an interactive media or cloud-gaming case, decompose end-to-end delay, distinguish measurable delivery quality from user experience, then propose controls and their trade-offs.

Reusable answer frame: Decompose delay into input / capture, encoding or processing, queueing, network transmission, loss recovery, decoding, buffering, and playout. Distinguish latency, jitter, loss, throughput, intrinsic QoS, and perceived QoS / QoE. Select a control matched to the symptom: adaptive bitrate, jitter buffer, FEC or concealment, priority queueing, congestion control, or a shorter encode / playout path. Explain the trade-off: a larger buffer smooths jitter but increases interaction delay; higher quality consumes more bandwidth; retransmission may arrive too late for real-time media.

Priority 6 – Error Detection, Redundancy And Recovery

Frequency: 5/7 directly. It is less prominent in 2024/25, but Hamming distance returned in the newest paper.

Appears as:

  • 2025/26 – Q2(b) Hamming Distance for Hamming (7, 4) and 8-bit ASCII with parity [4].
  • 2023/24 and 2021/22 – Hamming (7, 4) error detection and correction.
  • 2022/23 – RAID-0/1/5 [4] and backward recovery in dynamic software redundancy [3].
  • 2018/19 and 2017/18 – RAID, SEC, N-modular redundancy, voter types, and software redundancy.

Consolidated most-asked question:

Choose or explain an error-control or redundancy mechanism, identify which fault or error it covers, and state the independence or coverage assumption it needs.

Reusable answer frame: Define fault → error → failure. For Hamming questions, state the codeword length, number of data / parity bits, and the minimum Hamming distance; show which detection or correction claim follows from it. For RAID, distinguish striping, mirroring, and distributed parity as well as performance and failure trade-offs. For voters and replicas, specify the voter rule and explain common-mode failure: replicas are not independent merely because there are several of them. For backward recovery, show the saved consistent state, failure detection, rollback, and the problem of already-emitted external effects.

Distinct Lower-Frequency Families

Do not let the newest papers erase these, but revise them after the priorities above.

  • Logical clocks and causality: Lamport clocks versus vector clocks appears in 2022/23 Q4(a), 2023/24 Q2(b), and 2024/25 Q2(a). Draw the messages, apply each update rule, then show that scalar Lamport timestamps preserve happened-before but cannot identify concurrency.
  • Lunar or radio navigation: lunar GNSS / multilateration appears in 2022/23 Q1(a) and 2025/26 Q1(a). Explain geometry, timing, reference signals, and whether an external differential correction source is available.
  • Core Web Vitals and resource waterfalls: appears in 2023/24 Q5(b) and Q6. Know the purpose of LCP, FID and CLS, and use the stated impact and distance fractions for a CLS calculation.
  • WCET and non-re-entrant code: older papers use loop bounds, longest paths, volatile variables, and interrupt risks. These remain useful foundations for scheduling answers even when not a standalone recent question.

  2. Do the matching 2024/25 topics: clocks / PTP, RM / CE, priority inheritance / memory locking, QUIC, analysis tools, QoS and jitter buffers.
  3. Use 2023/24 to practise the compulsory-question variant and strengthen CE / RM / EDF comparison, PTP transparent clocks, and QUIC fundamentals.
  4. Use 2022/23 and 2021/22 for Priority Ceiling, PTP architecture, NTP robustness, logical clocks, POSIX signals, RAID, and recovery.
  5. Use 2018/19 and 2017/18 for broad practice in FEC, VoIP, voters, memory locking, NTP interpretation, and the classic RM-versus-EDF counterexample.
