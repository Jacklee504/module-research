How to use this bank

  • These are revision questions derived from the official CT4111 description and learning outcomes.
  • They are not past-paper questions and do not predict the assessment format or mark allocations.
  • For every scenario answer, state the lifecycle stage, explain the role and limit of GenAI, then justify the human controls that preserve software quality.
  • Use the questions as both written practice and prompts for small, version-controlled lab exercises.

Revision questions

1. Capabilities, limitations and failure modes

Official outcome: explain capabilities, limitations and failure modes of Generative AI across the software development lifecycle.

  1. For requirements elicitation, architecture design, implementation, testing and maintenance, give one useful task a generative AI tool can support. For each, name one reason the output must be checked by an engineer.
  2. A team asks an LLM to explain a legacy payment module and propose a change. Analyse three distinct failure modes that could produce an unsafe or misleading recommendation, and explain how the team could detect each one.
  3. “A fluent answer is evidence of a correct answer.” Critically evaluate this statement in the context of debugging a production incident. Distinguish plausibility, correctness, completeness and evidence.
  4. Explain how hallucinated APIs, stale framework knowledge and omitted edge cases differ. For each failure mode, give a software-engineering example and a verification technique.
  5. An AI assistant proposes a change that appears to solve the reported bug but silently weakens an existing access-control rule. Explain why this type of failure can be hard to detect and how a team can reduce its likelihood.
  6. Compare using GenAI as a brainstorming partner with using it as an authority on a technical decision. What evidence should move a suggestion from “candidate idea” to “accepted engineering decision”?

    7. 2. GenAI across the software development lifecycle

    Official outcome: apply tools effectively and critically to requirements, architecture and design, implementation, testing, deployment and maintenance.

    1. A university needs a room-booking service. Write a sequence of prompts and human checks that would use GenAI to turn a short stakeholder request into testable functional and non-functional requirements.
    2. Compare two ways of using GenAI to assist an architecture decision: asking for a complete solution in one prompt, or iteratively comparing alternatives against explicit quality attributes. Which is more defensible, and why?
    3. Design an AI-assisted workflow for adding a new API endpoint, from issue description to deployment. Identify the artefacts, validation gates and accountable human roles at each stage.
    4. Show how GenAI could help create a test strategy for a password-reset feature. Separate what the tool may draft from what must be validated against the actual system, threat model and acceptance criteria.
    5. A deployment has failed after a configuration change. Explain how to use GenAI responsibly during diagnosis without allowing it to make unsupported production changes or exposing sensitive operational data.
    6. For a maintenance task involving a deprecated library, describe how you would use GenAI to explore migration options while retaining ownership of dependency selection, compatibility testing and rollout planning.

      7. 3. Quality, readability, testability and maintainability

      Official outcome: design, implement and evolve systems with GenAI-assisted workflows while maintaining software quality.

      1. An AI tool generates a 250-line method that passes its initial tests. What questions would you ask before accepting it into the codebase? Cover readability, correctness, coupling, error handling and testability.
      2. Given a working but duplicated AI-generated implementation of validation rules in three services, propose a refactoring plan. Explain how you would use automated tests to show that the refactor has preserved behaviour.
      3. Evaluate the claim: “If GenAI makes implementation faster, maintainability is automatically improved.” Use a concrete example involving an unfamiliar dependency, generated code and future change requests.
      4. Define a quality gate for AI-generated code before merge. Include static analysis, unit and integration testing, security checks, documentation and human review; explain the value of each.
      5. An AI-generated feature has 95% branch coverage but users report failures for invalid input. Explain why coverage alone is insufficient and propose tests that would reveal the missing behaviour.
      6. How would you decide whether to accept, rewrite or reject an AI-generated implementation that is correct but inconsistent with the project’s existing abstractions and naming conventions?

        7. 4. Version control, experimentation and review

        Official outcome: use version control and collaborative development practices appropriately, including safe experimentation, rollback and review.

        1. Describe a safe Git workflow for trying an AI-suggested database migration that may be incorrect. Include branching, review, test environments, rollback and documentation.
        2. A developer pastes an AI-generated patch directly onto the main branch because it fixes a failing build. Analyse the risks and specify a better pull-request workflow.
        3. Draft a concise code-review checklist for AI-assisted changes. Your checklist must make reviewers assess provenance, scope, tests, security, readability and the change’s compatibility with existing design decisions.
        4. A team wants to compare three AI-generated implementation approaches. Design an experiment that keeps each option isolated, reproducible and easy to discard if it fails.
        5. Explain why a useful commit history matters especially when GenAI is used. What should a reviewer be able to learn from commits, pull-request discussion and linked issues?
        6. A rollback restores the previous application version but leaves a changed database schema. Analyse why the rollback is incomplete and propose a safer release and recovery plan.

          7. 5. Evaluating AI-assisted workflows

          Official outcome: evaluate workflows using suitable qualitative and quantitative criteria, while recognising uncertainty and bias.

          1. Choose four quantitative and three qualitative criteria for evaluating whether an AI code-completion tool improves a team’s testing workflow. Explain why “lines of code produced” is an inadequate success measure on its own.
          2. A pilot reports that developers using GenAI complete tickets 25% faster. What further evidence is needed before concluding that the workflow is better? Consider defects, review effort, task difficulty, developer experience and maintainability.
          3. Design a small, fair comparison between an AI-assisted and non-AI-assisted bug-fix workflow. State the research question, controls, measures, sources of uncertainty and limitations of the result.
          4. Explain how selection bias could make an AI-assistance pilot look more successful than it really is. Give two design changes that would make the evaluation more credible.
          5. A team evaluates AI-generated tests by counting how many tests compile. Identify stronger measures of test quality and explain what each reveals that compilation does not.
          6. Interpret this result: the AI-assisted group resolves more tasks, but its changes receive more review comments and more post-release defects. What conclusions are justified, what remains uncertain, and what should be tested next?

            7. 6. Ethical, legal, security and professional risks

            Official outcome: identify and manage risks arising from GenAI use in software engineering practice.

            1. A developer includes a confidential customer error log in a public GenAI prompt to obtain debugging help. Identify the ethical, legal, security and professional concerns, then propose a safer route to assistance.
            2. An AI tool suggests code copied from an unknown source and recommends adding a package that has not been approved by the organisation. Explain the intellectual-property, supply-chain and security checks required before reuse.
            3. Produce a risk register for a team adopting GenAI for customer-facing software. Include at least one risk each for privacy, bias, insecure code, over-reliance and accountability; for each, state a mitigation and residual risk.
            4. A team uses GenAI to rank job applicants based on free-text CVs. Identify potential bias and explain what technical, process and governance controls are needed before such a system could influence a decision.
            5. Distinguish responsibility, accountability and auditability in an AI-assisted engineering workflow. Why does recording prompts, inputs, outputs and human approvals matter?
            6. An AI coding assistant proposes disabling certificate validation to resolve a development-environment error. Explain the security consequences and describe a professional response that enables legitimate testing without normalising an unsafe workaround.

              7. 7. Teamwork, communication and trade-offs

              Official outcome: work effectively in teams and communicate GenAI decisions, trade-offs and risks clearly.

              1. Your team disagrees about whether to use an LLM to generate acceptance tests. Prepare a short decision record that states the context, alternatives, decision criteria, chosen approach, safeguards and review date.
              2. A product manager wants to automate release-note generation with GenAI; a security engineer objects. Explain how the team can reach and communicate a reasoned decision rather than treating the issue as simply “for” or “against” AI.
              3. During a project retrospective, the team finds that GenAI accelerated initial implementation but increased code-review time. Explain how you would present this trade-off to stakeholders and recommend the next workflow experiment.
              4. Two developers obtain incompatible AI suggestions for the same feature. Describe how the team should compare them using requirements, architecture constraints, evidence and review rather than personal preference.
              5. Write the outline of a team agreement for GenAI use. Cover permitted tools, data-handling boundaries, review expectations, documentation and escalation of uncertain or risky outputs.
              6. A junior developer relies heavily on GenAI while a senior developer rejects it entirely. Explain how a team lead can create a learning-focused process that maintains standards and gives both developers constructive responsibilities.

              • LO3: Questions 13–18 — quality-focused design, implementation and evolution.
              • LO4: Questions 19–24 — disciplined version control, experimentation and review.
              • LO5: Questions 25–30 — qualitative and quantitative evaluation, uncertainty and bias.
              • LO6: Questions 31–36 — ethical, legal, security and professional risk management.
              • LO7: Questions 37–42 — team decisions, communication and trade-offs.
