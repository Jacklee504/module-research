  • GenAI across the lifecycle

    Topic 1: where can GenAI assist requirements, design, implementation and testing? Name a failure mode and a human check at each stage.

    Reveal answer plan
    • Software engineering includes requirements, design, implementation, verification and maintenance, not just producing code.
    • Connect each generated output to a review criterion such as stakeholder validation, quality attributes, tests or traceability.
    • Check incorrect assumptions, insecure code and missing context before using any output.

  • Tools and review

    Topic 2: compare autocomplete, conversational editing and autonomous agents for one coding task. Show how version control and tests make work reviewable.

    Reveal answer plan
    • Compare each mode’s autonomy, available context and human control.
    • Start from a small task and acceptance check; inspect diffs, run focused tests and keep a recoverable version-control history.
    • Name a failure mode such as unintended edits or false confidence, plus the check that catches it.

  • Prompt and context design

    Topic 3: rewrite an ambiguous coding request with task, context, inputs, constraints and output format. Explain how you would keep context relevant.

    Reveal answer plan
    • Specify desired behaviour, relevant repository facts, examples or tests, and a reviewable output format.
    • Ask for missing details when ambiguity changes correctness. Keep context current and focused.
    • Verify the response against requirements and tests; extra context can distract or become stale.
    Canvas Topic 3Revision questions
  • Requirements engineering

    Topic 4: outline an AI-assisted path from an initial request to testable requirements. Where must stakeholders or domain experts intervene?

    Reveal answer plan
    • Identify stakeholders and goals, elicit functional and quality needs, then resolve conflicting or missing assumptions.
    • Draft clear, testable requirements with traceability to the source and acceptance criteria.
    • Have domain experts validate meaning, priority and feasibility before design; AI cannot supply missing organisational facts reliably.
    Canvas Topic 4Revision questions
  • Architecture decisions

    Topic 5: compare AI-suggested architectural alternatives against measurable quality criteria and record your decision.

    Reveal answer plan
    • State requirements, constraints and quality attributes before generating alternatives.
    • Compare options on relevant performance, security, maintainability, availability, cost and team context.
    • Record the chosen architecture, reasons, rejected options, risks and consequences; have a human verify claims and trade-offs.
    Canvas Topic 5Revision questions
  • Implementation workflows

    Topic 6: for a moderate-risk change with clear tests, choose among reviewer, support, junior-developer, test-driven and high-autonomy workflows.

    Reveal answer plan
    • State the task, acceptance criteria and available tests before choosing a workflow.
    • Compare how much work the tool does and what a human can verify. More autonomous workflows need stronger specification and review.
    • Keep the change bounded, inspect the diff, run tests and retain an accountable human decision. Name a risk such as hidden defects or over-trust.
