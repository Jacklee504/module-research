CT4101 Topic Guide

Machine Learning Foundations

Start here: decide what kind of learning problem you have before choosing an algorithm.

Exam-use protocol

Before writing, identify the command word: calculate/trace requires an ordered derivation; explain requires a definition, mechanism and assumption; compare/design requires matched criteria, a justified choice and a limitation. The topic-specific recall and worked routes below are the material to adapt—not text to copy blindly.

Part-by-part recall: definitions, assumptions and mechanics

Definitions: supervised learning maps features x to labelled target y; classification predicts a discrete label, regression a numeric value, clustering finds unlabelled structure. Question cue: infer task from target type, then justify algorithm and metric; accuracy is not universal.

Worked practice 1 — paper-style synthesis (recurring-topic pattern; not a quoted paper prompt) task choice

Question demand: Classify spam versus predict house price. Plan/choice: identify y. Worked answer: spam is binary classification (e.g. logistic/tree) with precision/recall; price is regression (e.g. kNN/regressor) with MAE/RMSE. Mark-winning points: application, algorithm, metric linked. Common trap: calling all prediction classification.

Worked practice 2 — synthesis / design

Question demand: Select a learning approach for fraud with rare positives. Plan/choice: specify labels, split, imbalance method and decision metric. Worked answer: use supervised classification, stratified validation, class weighting/resampling, PR/recall and threshold chosen from costs; audit false positives. Mark-winning points: target and objective. Common trap: high accuracy proves utility.

Purpose and relevance

Machine learning (ML) learns a pattern from examples so it can make useful predictions on new examples. This vocabulary supports almost every other CT4101 answer.

What a question really asks — answer plan

“Classify this task” asks you to identify the target and the available labels. State the task, name the learning setting, give a suitable algorithm, then justify it from the output type.

Prerequisites, vocabulary and formulas

  • Feature/input x: information used to predict.
  • Target/label y: wanted output.
  • Supervised: training examples include y; unsupervised: no supplied y.
  • Classification: a discrete class; regression: a number; clustering: groups similar unlabelled cases.
  • Training / validation / test: fit / choose / final unbiased check.

Step-by-step method

  1. Write what one row represents.
  2. Ask whether a correct output is supplied.
  3. If yes, decide whether it is a class or number. If no, consider clustering.
  4. Name one algorithm and one sensible evaluation measure.

Worked practice 3 — foundational calculation

Question: A hospital has past patient records labelled “readmitted” or “not readmitted”. What task is this?

Model answer: This is supervised binary classification: each record has an input and a two-valued label. Logistic regression, a decision tree, or kNN could predict the class. Accuracy alone may be insufficient if readmissions are rare; report recall and precision too.

Question interpretation and independent practice

Prompt 1

Predict next month’s electricity use from past weather and use. Check: supervised regression because the target is numeric.

Exam bridge

Explain classification, regression and clustering with one application each, and contrast supervised and unsupervised learning. Check: define all four terms, tie classification/regression to labelled outputs, and give a clustering example with no labels; do not say clustering predicts a known class.

High-value traps and corrections

Integrated syllabus-based practice - frame the task [8 marks]

Scenario. A council has historic applications with features (household size, area, rent) and outcomes: grant approved yes/no and eventual annual energy saving in kWh. Propose two learning tasks, suitable targets and evaluation measures.

Question-demand diagnosis: decide whether each target is categorical or continuous, then make evaluation match the decision.

Fastest route: map approval to classification and kWh to regression, naming an error measure and a validation split.

Worked answer: Approval is binary classification; estimate a calibrated approval probability and assess precision/recall or ROC alongside fairness by relevant groups, because false approval and rejection costs differ. Energy saving is regression; predict kWh and evaluate MAE or RMSE on a held-out time-aware set. Do not use accuracy for the continuous target. Both tasks need representative training data, a baseline and monitoring for policy or population shift.

Topic-specific trap: a prediction target is not a feature available only after the council has made its decision.

  • Calling every prediction “classification”.
  • Confusing a feature with a label.
  • Claiming unsupervised learning has a correct answer for every training row.

Final answer checklist

  • Can I identify x and y?
  • Can I justify task type from y?
  • Can I name an appropriate metric?
