CT4101 Topic Guide

Model Selection and Hyperparameters

Choose a model configuration using evidence that is separate from final testing.

Exam-use protocol

Before writing, identify the command word: calculate/trace requires an ordered derivation; explain requires a definition, mechanism and assumption; compare/design requires matched criteria, a justified choice and a limitation. The topic-specific recall and worked routes below are the material to adapt—not text to copy blindly.

Part-by-part recall: definitions, assumptions and mechanics

Definitions: parameters are learned from data; hyperparameters (k, depth, regularisation) are selected by validation. k-fold CV repeatedly holds out one fold; final test remains untouched. Question cue: give split, search space, metric and unbiased final estimate.

Worked practice 1 — paper-style synthesis (recurring-topic pattern; not a quoted paper prompt) CV

Question demand: Choose k for kNN. Plan/choice: stratified 5-fold CV on training set. Worked answer: evaluate each candidate across held-out folds, average the stated metric, choose once, retrain on all training data and test once. Mark-winning points: fold roles. Common trap: tune on test.

Worked practice 2 — synthesis / design

Question demand: Compare tree depths for rare-event detection. Plan/choice: nested/held-out validation using recall/PR rather than accuracy. Worked answer: tune depth/min-leaf with stratified folds, report variation, lock configuration then assess the independent test set. Mark-winning points: objective matches task. Common trap: treat CV folds as final test.

Purpose and relevance

Model selection compares candidate algorithms and settings fairly. A hyperparameter is chosen before fitting, such as k in kNN or maximum tree depth; a parameter is learned from data.

What a question really asks — answer plan

“Explain cross-validation/grid search” asks you to protect the test set, explain the repeated fitting loop, then select by an appropriate mean validation metric. Mention nested evaluation or a final untouched test only when relevant.

Prerequisites, vocabulary and formulas

  • Validation set: data used to choose a model; test set: final estimate.
  • k-fold CV: split training data into k folds; train on k−1 and validate on the remaining fold; average scores.
  • Grid search: evaluate every listed setting combination.
  • Choose the metric to match the task: e.g. F1 for a rare positive class, RMSE for numeric error.

Step-by-step method

  1. Hold out a final test set once.
  2. Specify candidate models/hyperparameter values.
  3. For each candidate, run CV only on training data.
  4. Average the validation score and choose the best setting.
  5. Refit the selected setup on all training data, then evaluate once on test data.

Worked practice 3 — foundational calculation

Question: Three-fold CV scores for k=3 are .70, .80, .75; for k=5 they are .80, .78, .82. Which k wins?

Model answer: Mean for k=3 is .75. Mean for k=5 is .80, so select k=5, then refit kNN with k=5 on the whole training set. The test set must not have influenced this choice.

Question interpretation and independent practice

Prompt 1

Is tree depth a parameter or hyperparameter? Check: a hyperparameter chosen by the procedure before fitting.

Exam bridge

Design a grid-search and five-fold CV process for choosing k∈{1,3,5} and a distance metric. Check: there are six combinations; each gets five fits/validation scores; average a stated metric; select best; only then use the untouched test set.

High-value traps and corrections

Integrated syllabus-based practice - select a regulariser [8 marks]

Scenario. Three logistic-regression regularisation values have five-fold validation AUC means: C=.01: .74, C=1: .82, C=100: .81. Describe a selection procedure and a defensible conclusion.

Question-demand diagnosis: tune without allowing the final test set to influence the choice.

Fastest route: fix folds, compare mean and variability, refit the chosen setting on all training data, test once.

Worked answer: Use the same stratified folds for every C, inspect fold variation as well as means, and choose C=1 unless its advantage over C=100 is within noise and simplicity favours stronger regularisation. Refit with the selected C using all non-test training records, then report a single untouched test AUC with confidence information. The test set must not select C or the reported performance becomes optimistically biased.

Topic-specific trap: repeated peeking at test AUC turns it into another validation set.

  • Tuning repeatedly on test results.
  • Calling k-fold CV “five training sets” without explaining the held-out fold.
  • Optimising accuracy when the stated objective needs recall/F1.

Final answer checklist

  • Are tuning and final test separate?
  • Did I distinguish parameter from hyperparameter?
  • Did I average fold scores?
