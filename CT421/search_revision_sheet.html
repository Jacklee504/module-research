Search and Adversarial Search

The recurring Question 1 material: traversal, game trees, minimax, alpha-beta pruning, MCTS, and novelty search.

Exam-use protocol

Before writing, identify the command word: calculate/trace requires an ordered derivation; explain requires a definition, mechanism and assumption; compare/design requires matched criteria, a justified choice and a limitation. The topic-specific recall and worked routes below are the material to adapt—not text to copy blindly.

Part-by-part recall: definitions, assumptions and mechanics

Definitions: BFS expands shallowest, DFS deepest, uniform-cost lowest path cost, A* lowest g+h with admissible h. Minimax backs MAX/MIN leaf utilities; alpha-beta prunes branches that cannot change result. Question cue: state frontier rule, completeness/optimality, then trace.

Worked practice 1 — paper-derived adversarial search

Question demand: Back up a small MAX/MIN tree. Plan/choice: label levels, evaluate leaves, take min then max. Worked answer: each MIN returns its smallest child, root MAX chooses largest returned value; alpha-beta skips a child once its bound cannot beat an ancestor bound. Mark-winning points: labelled direction/order. Common trap: pruning changes minimax value.

Worked practice 2 — synthesis / design

Question demand: Choose search for an optimal path with non-negative costs. Plan/choice: compare UCS/A* and heuristic condition. Worked answer: UCS is optimal but expands by g only; A* remains optimal with admissible/consistent h and usually expands less. Report time/space caveat. Mark-winning points: condition for guarantee. Common trap: BFS optimal for unequal costs.

Tree Search

Breadth-first search (BFS)

BFS explores all nodes at depth 0, then depth 1, then depth 2, using a queue.

  • Complete if the branching factor is finite.
  • Finds a shortest path when every step has equal cost.
  • Time and memory are both high: approximately O(bd).

Depth-first search (DFS)

DFS follows one branch as deeply as possible before backtracking, using a stack or recursion.

  • Low memory: approximately O(bm), where m is maximum depth.
  • Time can be O(bm).
  • Not complete in an infinite tree and does not guarantee a shortest path.

Iterative deepening (IDDFS)

Iterative deepening runs DFS repeatedly with limits 0, 1, 2, and so on.

  • Complete and finds a shortest shallow solution with equal step costs.
  • Uses DFS-like memory: approximately O(bd).
  • Repeats work near the root, but this overhead is usually small.

Adversarial Search

Game tree and minimax

A game tree represents possible moves. Minimax assumes one player tries to maximise a score while the opponent tries to minimise it. Terminal positions receive scores, then values are backed up the tree: max nodes choose the largest child value and min nodes choose the smallest.

MAS connection: Minimax models two competing agents. For a large game tree, use a depth limit and a heuristic evaluation function rather than expanding to every terminal state.

Alpha-beta pruning

Alpha-beta pruning avoids searching branches that cannot change the final minimax decision.

  • Alpha: the best value found so far for MAX.
  • Beta: the best value found so far for MIN.
  • Prune when alpha is greater than or equal to beta.
  • It returns the same answer as minimax but examines fewer nodes.

Monte Carlo Tree Search (MCTS)

MCTS builds a tree gradually through four stages: select a promising node, expand a new child, simulate a rollout, and backpropagate the result. It is useful when a full game tree is too large to enumerate.

Novelty search

Novelty search rewards solutions for behaving differently from previously explored solutions rather than only for improving a fitness score. It can escape deceptive local optima, but needs a useful behaviour measure and may explore irrelevant novelty.

Question interpretation and independent practice

  • For a comparison question, copy its headings first: visit order, time, space, completeness, and optimality if relevant. Fill in one fact for each algorithm under each heading.
  • For minimax, start with the game tree: legal moves become children, terminal states get scores, then say MAX takes the largest value and MIN the smallest. Add alpha-beta only after minimax is clear.
  • For an extension question, identify why standard minimax fails: either more than two competing players or too many states. Then choose the matching fix: a utility vector, a depth limit and heuristic, or sampling with MCTS.

Exam Practice: Search

Question 1: BFS, DFS, and iterative deepening (2023/24 and 2024/25, 9-10 marks)

Question: Compare BFS, DFS, and iterative deepening in visit order, time complexity, space complexity, and completeness.

Short model answer:

  • BFS visits level by level. It is complete and shortest-path for equal costs, but uses O(bd) time and memory.
  • DFS follows one branch before backtracking. It uses O(bm) memory but can take O(bm) time, is not complete in infinite spaces, and is not optimal.
  • IDDFS repeats depth-limited DFS. It is complete and optimal for equal costs like BFS, while using O(bd) memory like DFS.

Question 2: Minimax and alpha-beta pruning (2021/22 and 2024/25, 8-10 marks)

Question: Explain minimax and alpha-beta pruning with respect to a two-player game.

Short model answer:

  • Build a game tree of legal moves. Score terminal states, or use a heuristic at a depth limit.
  • MAX chooses the highest child value; MIN chooses the lowest. Backing values up identifies MAX's best move.
  • Alpha-beta keeps MAX's best alpha and MIN's best beta. When alpha >= beta, the remaining branch cannot affect the choice and is pruned.
  • Pruning gives the same minimax move while searching fewer positions.

Question 3: Monte Carlo Tree Search (2024/25, 5 marks)

Question: Explain the main aspects of MCTS.

Short model answer: MCTS repeatedly selects a promising node, expands one new child, simulates a rollout, and backpropagates the result. It balances exploring less-visited nodes with exploiting nodes that have good results. It is useful for very large game trees where full minimax search is infeasible.

Question 4: Extending minimax (2021/22 and 2022/23, 8-10 marks)

Question: Minimax is usually applied to a two-player game where all states can be listed. Explain how it could be extended for a three-player game and for a game where all states cannot be enumerated.

Short model answer:

  • For three players, store a utility vector such as (u1, u2, u3). At each player's turn, choose the successor that maximises that player's own utility. This is often called max-n.
  • When the tree is too large, search only to a fixed depth and use a heuristic evaluation function for unfinished positions.
  • Alpha-beta pruning can reduce the work in the two-player case; MCTS is another option when the branching factor is very large.

Question 5: Novelty search (2022/23 and 2023/24, 7 marks)

Question: Explain the motivation for novelty search and, using a domain of your choice, explain how it could be implemented.

Short model answer:

  • Novelty search rewards different behaviour rather than direct progress on the objective, helping search escape deceptive local optima.
  • For a maze robot, define behaviour as the final position or the route taken. Keep an archive of sufficiently novel behaviours.
  • Give high novelty scores to candidates far from their nearest behavioural neighbours, then select them for future generations.
  • A weakness is that novelty depends on a good behaviour descriptor; otherwise it may explore unhelpful differences.

Integrated paper-style practice - adversarial search [9 marks]

Scenario. A root MAX has two MIN children. The left MIN has terminal values 3 and 5; the right MIN has terminal values 2 and an unvisited final leaf. Evaluate left-to-right with alpha-beta pruning. State MAX's move and whether the last leaf is needed.

Question-demand diagnosis: this is a value-backup trace, not merely a definition of alpha-beta. Labels, visit order and a pruning justification earn the marks.

Fastest route: evaluate left MIN first to set root alpha=3. At right MIN, the first leaf sets beta=2; beta is then no greater than alpha.

Worked answer: Left MIN returns min(3,5)=3, so MAX's alpha becomes 3. Right MIN's first child returns 2, so its beta is 2. Because beta ≤ alpha, the unvisited leaf cannot make right MIN return a value above 2, and cannot displace MAX's already available value 3. Prune it. The root chooses the left move with minimax value 3. The prune changes work, not the minimax decision. With a depth limit, terminal values would instead be heuristic evaluations and should be justified as estimates.

Topic-specific trap: never prune a branch merely because its current value looks poor without comparing the relevant alpha and beta bounds.

High-value traps and final review

Worked example: choosing BFS

Problem: A maze has equal-cost moves and the goal is first found at depth 3. Which basic search should find a shortest route?

Model reasoning: The step costs are equal and the question asks for a shortest route. BFS expands level by level, so it reaches every depth-3 route before any deeper route. Therefore choose BFS; mention that its memory use is the trade-off.

Common mistakes

  • Calling DFS optimal or complete in an infinite search tree.
  • Claiming alpha-beta changes the move chosen by minimax.
  • Giving a complexity without stating whether it is time or space.

Final checklist

  • State visit order, completeness, optimality, time, and space when comparing searches.
  • For minimax, label MAX/MIN and back values up from leaves.
  • For alpha-beta, state that pruning preserves the minimax result.
