OpenSSL

Use a cryptographic library by defining the desired property and evaluating its configuration.

Rapid exam refresher

  • A CSR carries public key, requested subject/SAN and applicant signature; it is not a certificate.
  • Workflow: protected private key → CSR with SAN → CA leaf/chain → inspect → deploy/test.
  • Inspect SAN, issuer, validity, key, extensions and chain; command success is not semantic validation.
  • Choose authenticated encryption, strong randomness/password KDF and restricted key permissions.

Medium practice — 15 marks

Prepare TLS material for service.example.ie. (a) [5] workflow. (b) [5] inspect. (c) [5] operational protections.

Answer for every part

(a)

Answer: generate/protect key, create CSR including SAN, obtain CA-signed leaf and deploy correct intermediate chain. Trap: assuming CN replaces SAN.

(b)

Answer: verify SAN, time, serverAuth, issuer chain and key match before deployment. Trap: inspecting only expiry.

(c)

Answer: restrict key access/HSM; automate renewal and stage test. Trap: emailing private key.

Hard practice — 15 marks

Encrypt backups with a password and prove origin. (a) [5] select encryption. (b) [5] add origin evidence. (c) [5] recovery.

Answer for every part

(a)

Answer: derive key with salted strong KDF and use AEAD with unique nonce. Trap: raw password as key.

(b)

Answer: sign a versioned manifest with protected private key. Trap: confusing encryption with signature.

(c)

Answer: version keys, access-control recovery copies and conduct restore tests. Trap: untested backup.
