CT4104 overview

CT4104 Topic Guide

Threat analysis

Make security decisions traceable from assets and threats to mitigations and residual risk.

Rapid exam refresher

  • Begin with scope, assets, actors, data flows and trust boundaries.
  • STRIDE prompts spoofing, tampering, repudiation, information disclosure, denial of service and elevation of privilege.
  • Record likelihood, impact, owner, mitigation and residual risk; treat by avoid, mitigate, transfer or accept.
  • A mitigation must close a specific attack path and have a verification method.

Medium practice — 15 marks

A web app uploads documents to a background converter. (a) [5] describe boundaries/assets. (b) [5] identify two STRIDE paths. (c) [5] mitigate and prioritise.

Answer for every part

(a)

Route: trace browser→API→queue→converter→storage. Answer: boundaries occur at API, worker and storage; assets include document content, tenant identity and converter host. Trap: omitting asynchronous queue.

(b)

Route: give attacker, boundary, harm. Answer: crafted file can tamper by exploiting converter; predictable object URL discloses another tenant’s document. Trap: naming STRIDE letters only.

(c)

Route: map control to path. Answer: sandbox converter/no network/type-size limits; opaque IDs plus server authorisation. Prioritise RCE for impact. Trap: generic ‘encrypt it’.

Hard practice — 15 marks

An API accepts partner webhooks. (a) [5] model spoofing/replay. (b) [5] design validation. (c) [5] assess residual DoS risk.

Answer for every part

(a)

Answer: attacker forges source or replays a genuine state-changing callback across the Internet boundary. Trap: trusting source IP alone.

(b)

Answer: verify MAC/signature over canonical body, timestamp and nonce; reject expired/reused nonce and use idempotency key. Trap: verifying signature after processing.

(c)

Answer: rate limits/queue/backpressure reduce volume but valid signed traffic can still consume capacity; monitor and define shedding policy. Trap: calling authentication DoS prevention.
