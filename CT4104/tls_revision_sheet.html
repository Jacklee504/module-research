CT4104 Topic Guide

TLS

Explain secure-channel components by the security job each performs.

Rapid exam refresher

  • TLS authenticates server (optionally client), negotiates algorithms and derives fresh symmetric traffic keys.
  • Validate certificate chain, SAN hostname, time and usage; ephemeral (EC)DHE provides forward secrecy.
  • Finished messages bind handshake transcript; AEAD protects application data.
  • TLS does not authorise application actions, validate input or hide all metadata.

Paper evidence and scope

No local CT4104 papers exist: practice is syllabus-based.

Medium practice — 15 marks

Client connects to shop.example.ie. (a) [5] TLS 1.3 security story. (b) [5] certificate check. (c) [5] non-TLS control.

Answer for every part

(a)

Answer: negotiate, validate server certificate/proof of key possession, perform ephemeral exchange, derive secrets and verify Finished before AEAD data. Trap: saying certificate encrypts all traffic.

(b)

Answer: SAN must include shop.example.ie, chain/signatures/time/usage must validate. Trap: accepting issuer name alone.

(c)

Answer: enforce application session authorisation, CSRF and input validation. Trap: TLS makes app safe.

Hard practice — 15 marks

Staging disables certificate verification. (a) [5] threat. (b) [5] safe trust. (c) [5] verification tests.

Answer for every part

(a)

Answer: active MITM can terminate TLS and read/alter traffic. Trap: calling it merely a warning.

(b)

Answer: trust a dedicated staging CA or explicit controlled anchor, never permissive callback. Trap: shipping staging CA to public clients.

(c)

Answer: tests reject expired, wrong-host and untrusted certificates and assert policy. Trap: testing only successful connection.
