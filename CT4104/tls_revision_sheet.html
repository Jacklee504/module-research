TLS

Explain secure-channel components by the security job each performs.

Rapid exam refresher

  • TLS negotiates, validates peer, derives traffic keys and protects records.
  • certificate checks chain/SAN/validity/status.
  • ephemeral agreement gives forward secrecy.
  • TLS is not authorisation.

Purpose, scope and examiner demand

TLS is explicit CT4104 scope and illustrates analysis of cryptographic network protocols.

Exam focus by part

  • TLS negotiates, validates peer, derives traffic keys and protects records.
  • certificate checks chain/SAN/validity/status.
  • ephemeral agreement gives forward secrecy.
  • TLS is not authorisation.

Question-demand diagnosis and answer plan

State endpoints and threats; explain authentication, key establishment and protected application data; then identify configuration or validation failure.

Question-type cues

  • Application cue: Why reject trusted certificate with wrong SAN?
  • Analysis cue: TLS terminates at load balancer then clear HTTP reaches backends.

Definitions, notation and discriminating comparisons

  • Handshake: negotiate parameters and establish keys.
  • Certificate: server identity-to-public-key evidence.
  • Key exchange: derives shared session secrets.
  • Session keys: symmetric keys protecting data.
  • Authenticated encryption: confidentiality plus tamper detection.

Step-by-step methods and solution routes

  1. Name client, server and active/passive attacker.
  2. Validate the server certificate and intended hostname.
  3. Describe key establishment and derived session keys.
  4. Explain authenticated protection of application data and a failure case.

Reasoning checkpoints

  1. Use and justify: TLS negotiates, validates peer, derives traffic keys and protects records.
  2. Use and justify: certificate checks chain/SAN/validity/status.
  3. Use and justify: ephemeral agreement gives forward secrecy.
  4. Use and justify: TLS is not authorisation.

Worked examples and method extensions

A browser validates shop.example’s certificate, completes a key exchange, then uses fresh symmetric session keys for encrypted, integrity-protected requests. Skipping hostname validation permits a certificate for another site to mislead the client.

Medium practice — question demand

Why reject trusted certificate with wrong SAN?

Plan / choice of method

Select the governing concepts before calculating: TLS negotiates, validates peer, derives traffic keys and protects records.; certificate checks chain/SAN/validity/status.; ephemeral agreement gives forward secrecy. Apply them only under the assumptions stated in the question, and compare the result with the required condition.

Worked answer

Chain trust does not bind requested name; SAN mismatch means no authenticated target and permits MITM. Abort despite encryption.

Mark-winning points

Credit requires the named mechanism, all intermediate values or protocol states, the final conclusion, and these topic checks: TLS negotiates, validates peer, derives traffic keys and protects records.; certificate checks chain/SAN/validity/status.; ephemeral agreement gives forward secrecy.; TLS is not authorisation.

Common trap

Using “TLS” as a substitute for application authorisation.

Graded practice and hard extensions

Foundation

Why use symmetric keys after the handshake? Check: they efficiently protect bulk data after authentication/key establishment.

Exam bridge

Explain how TLS protects a login API. Check: include certificate validation, key establishment, confidentiality, integrity and a configuration caveat.

Hard practice — question demand

TLS terminates at load balancer then clear HTTP reaches backends.

Plan / choice of method

Model the failure or boundary first, then apply these page-specific concepts in order: TLS negotiates, validates peer, derives traffic keys and protects records.; certificate checks chain/SAN/validity/status.; ephemeral agreement gives forward secrecy. Finish by checking the final state against the deadline, security property, consistency contract, or performance requirement.

Worked answer

Treat termination as boundary; use mTLS/re-encryption internally, restrict paths, authenticate proxy identity, protect keys and retain server-side authorisation.

Mark-winning points

Credit requires the complete method sequence, explicit verification of the conclusion, and the limiting assumption/trade-off—not merely the recommended technology.
