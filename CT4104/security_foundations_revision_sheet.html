Purpose, scope and examiner demand

Confidentiality, integrity and authentication provide the applied-security language for CT4104’s official cryptography and protocol outcomes.

Exam focus by part

  • CIA separates secrecy, tamper detection and availability.
  • authentication identifies, authorisation permits.
  • threat/vulnerability/control and residual risk differ.
  • cue: map property to control.

Question-demand diagnosis and answer plan

Name the asset and adversary; state the required property; select a control; explain its limit and a supporting control.

Question-type cues

  • Application cue: Design payroll-record protection for employees and contractors.
  • Analysis cue: A leaked API token exported records and audit events were altered.

Definitions, notation and discriminating comparisons

  • Confidentiality: prevent unauthorised reading.
  • Integrity: detect unauthorised change.
  • Authentication / authorisation: establish identity / decide permitted actions.
  • Threat, vulnerability, control: possible harm, weakness, safeguard.

Step-by-step methods and solution routes

  1. Identify asset, attacker and trust boundary.
  2. Separate secrecy, tamper detection, identity and permission.
  3. Map each to encryption, MAC/signature, login and access control.
  4. State a residual risk and monitoring or recovery control.

Reasoning checkpoints

  1. Use and justify: CIA separates secrecy, tamper detection and availability.
  2. Use and justify: authentication identifies, authorisation permits.
  3. Use and justify: threat/vulnerability/control and residual risk differ.
  4. Use and justify: cue: map property to control.

Worked examples and method extensions

A records portal needs private, unaltered requests. TLS protects traffic confidentiality and integrity; login authenticates a user; authorisation restricts records. Encryption alone does not decide whether Alice may read Bob’s record.

Medium practice — question demand

Design payroll-record protection for employees and contractors.

Plan / choice of method

Select the governing concepts before calculating: CIA separates secrecy, tamper detection and availability.; authentication identifies, authorisation permits.; threat/vulnerability/control and residual risk differ. Apply them only under the assumptions stated in the question, and compare the result with the required condition.

Worked answer

TLS protects transit; sessions authenticate; object-level RBAC authorises each record; audit, backups and encryption-at-rest address detection/recovery. Encryption alone does not authorise.

Mark-winning points

Credit requires the named mechanism, all intermediate values or protocol states, the final conclusion, and these topic checks: CIA separates secrecy, tamper detection and availability.; authentication identifies, authorisation permits.; threat/vulnerability/control and residual risk differ.; cue: map property to control.

Graded practice and hard extensions

Foundation

What is lost if a download changes in transit? Check: integrity; confidentiality alone does not detect change.

Exam bridge

Propose controls for a payroll API. Check: map each property to a mechanism, include authorisation and explain one limit.

Hard practice — question demand

A leaked API token exported records and audit events were altered.

Plan / choice of method

Model the failure or boundary first, then apply these page-specific concepts in order: CIA separates secrecy, tamper detection and availability.; authentication identifies, authorisation permits.; threat/vulnerability/control and residual risk differ. Finish by checking the final state against the deadline, security property, consistency contract, or performance requirement.

Worked answer

Revoke/rotate token and sessions, preserve/scope evidence, enforce scoped short-lived credentials and least privilege, protect logs append-only and restore verified state.

Mark-winning points

Credit requires the complete method sequence, explicit verification of the conclusion, and the limiting assumption/trade-off—not merely the recommended technology.

Common trap

Claiming one control removes all risk.

  • Equating authentication with authorisation.
  • Claiming one control removes all risk.
