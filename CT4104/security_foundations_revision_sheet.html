CT4104 overview

CT4104 Topic Guide

Security foundations

Choose a control only after identifying the security property and asset it must protect.

Rapid exam refresher

  • CIA: confidentiality prevents disclosure, integrity prevents/detects unauthorised change, availability keeps an authorised service usable.
  • Authentication establishes an identity claim; authorisation decides permitted actions; accountability needs attributable protected logs.
  • Threat exploits a vulnerability; risk combines likelihood and impact. Controls are preventive, detective or corrective.
  • Use defence in depth, least privilege and fail-safe defaults to reduce blast radius.

Medium practice — 15 marks

A portal handles marks and password resets. (a) [5] classify assets and CIA failures. (b) [5] select controls for a compromised account. (c) [5] state residual risk and monitoring.

Answer for every part

(a) Demand, quickest route, answer, trap

Route: map asset → property → harm. Answer: marks and identity need integrity/confidentiality; reset availability matters. A changed mark is integrity loss; exposed reset token is confidentiality loss; unavailable reset is availability loss. Trap: listing CIA without applying it.

(b) Demand, quickest route, answer, trap

Route: name control and class. Answer: MFA and rate limiting are preventive; reset/audit alerts are detective; least-privilege admin roles contain impact. Trap: treating UI hiding as authorisation.

(c) Demand, quickest route, answer, trap

Route: name what remains and how it is seen. Answer: phishing/device theft remains; alert on impossible travel and review reset logs. Trap: claiming controls remove all risk.

Hard practice — 15 marks

A supplier has read-only reports but can export a whole database through an API. (a) [5] analyse failure. (b) [5] redesign access control. (c) [5] give verification evidence.

Answer for every part

(a)

Demand/route: find enforcement failure. Answer: excessive privilege and broken object-level authorisation permit bulk disclosure. Trap: blaming the user role rather than server policy.

(b)

Demand/route: enforce at API. Answer: use server-side tenant checks, scoped tokens, field filtering and export quotas. Trap: relying on hidden buttons.

(c)

Demand/route: test boundary and retain evidence. Answer: test cross-tenant IDs, preserve immutable audit records and alert on anomalous export. Trap: testing only happy path.
