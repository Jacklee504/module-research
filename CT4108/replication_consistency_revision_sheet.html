CT4108 Revision

Replication and Consistency

Explain how several copies improve service resilience while creating coordination choices.

Rapid exam refresher

  • Linearizable vs eventual contract.
  • quorum R+W>N intersection.
  • versions/conflict still required.
  • partitions force choice.

Purpose, scope and examiner demand

Replication maintains copies of data or service state. It can improve read capacity and availability, but updates must be propagated and readers need a stated consistency guarantee.

Exam focus by part

  • Linearizable vs eventual contract.
  • quorum R+W>N intersection.
  • versions/conflict still required.
  • partitions force choice.

Question-demand diagnosis and answer plan

  1. State why replicas exist: availability, latency, read scale or fault tolerance.
  2. Describe the update path: leader/primary, multi-writer or quorum.
  3. Name the consistency guarantee the client observes.
  4. Explain behaviour during delay, replica failure or partition.

Question-type cues

  • Application cue: For N=3 choose R,W with intersection.
  • Analysis cue: Partition creates concurrent updates.

Definitions, notation and discriminating comparisons

  • Replica: copy of state; primary/leader: chosen update coordinator.
  • Strong consistency: reads reflect an agreed current order of writes.
  • Eventual consistency: replicas converge if updates stop and communication recovers.
  • Stale read: a read returns an older replica value.
  • Quorum: sufficiently overlapping read/write groups; commonly discussed as read size R, write size W and replicas N.

Step-by-step methods and solution routes

Write down N, R and W. If each read set overlaps each write set, a reader can encounter a replica that saw the update; the usual condition is R + W > N. Then explain the operational assumption: failed or slow replicas must be detected, and conflicts still need a policy if multiple writers are allowed.

Reasoning checkpoints

  1. Use and justify: Linearizable vs eventual contract.
  2. Use and justify: quorum R+W>N intersection.
  3. Use and justify: versions/conflict still required.
  4. Use and justify: partitions force choice.

Worked examples and method extensions

With N=3, choose W=2 and R=2. Since 2+2>3, any read quorum overlaps any completed write quorum. After a write reaches two replicas, a two-replica read sees at least one updated copy. A client reading one replica instead may still see an old value.

Medium practice — question demand

For N=3 choose R,W with intersection.

Plan / choice of method

Select the governing concepts before calculating: Linearizable vs eventual contract.; quorum R+W>N intersection.; versions/conflict still required. Apply them only under the assumptions stated in the question, and compare the result with the required condition.

Worked answer

R=2,W=2 intersects and tolerates one unavailable replica under assumptions; version metadata selects latest. R=1/W=3 trade read/write availability.

Common trap

Graded practice and hard extensions

Prompt 1 — 7 marks

Compare primary-backup replication and eventual consistency for a profile service. Check: discuss update path, stale reads and availability trade-off.

Prompt 2 — 6 marks

For N=5, propose R and W that make quorums overlap. Check: show R+W>N and state what the inequality does and does not guarantee.

Hard practice — question demand

Partition creates concurrent updates.

Plan / choice of method

Model the failure or boundary first, then apply these page-specific concepts in order: Linearizable vs eventual contract.; quorum R+W>N intersection.; versions/conflict still required. Finish by checking the final state against the deadline, security property, consistency contract, or performance requirement.

Worked answer

Attach causal/version metadata, deterministic merge or user conflict, repair replicas and expose audit; no magical automatic conflict resolution.

Mark-winning points

Credit requires the complete method sequence, explicit verification of the conclusion, and the limiting assumption/trade-off—not merely the recommended technology.

Common trap

Forgetting conflict resolution for concurrent writers.

Topic-specific traps and diagnosis

  • Calling eventual consistency “always immediately correct.”
  • Using quorum arithmetic without stating N or failure assumptions.
  • Forgetting conflict resolution for concurrent writers.

Exam marking checklist

  • Did I state the client-visible guarantee?
  • Did I trace one write and one read?
  • Did I address a partition or stale read?
