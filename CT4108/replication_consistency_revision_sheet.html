CT4108 Revision

Replication and Consistency

Explain how several copies improve service resilience while creating coordination choices.

Rapid exam refresher

  • Replication improves availability/read scale but writes create divergence.
  • Linearizable means one real-time order; eventual consistency converges after updates stop; session guarantees include read-your-writes.
  • For N replicas, R+W>N gives read/write quorum intersection under protocol assumptions.
  • Choose conflict handling: CRDT/merge, version vector, LWW with loss risk, or user reconciliation.

Paper evidence and scope

No local CT4108 papers: syllabus-based practice.

Medium practice — 15 marks

Profile service N=3. (a) [5] choose R/W. (b) [5] stale-read trade-off. (c) [5] display-name conflict.

Answer for every part

(a) Answer: R=2,W=2 gives 4>3, so quorums intersect and tolerate one unavailable node for each operation. Trap: using R+W=N.

(b) Answer: weaker/one-replica reads reduce latency but can be stale; quorum may reject during partition. Trap: claiming replication is free availability.

(c) Answer: version updates and choose explicit LWW/reconciliation policy; report conflict if preservation matters. Trap: silent overwriting without policy.

Hard practice — 15 marks

Basket edits replicate eventually. (a) [5] anomaly. (b) [5] merge. (c) [5] client guarantee.

Answer for every part

(a) Answer: concurrent add/remove can resurrect/erase item. Trap: vague ‘inconsistency’.

(b) Answer: observed-remove set/operation tags preserves causal intent better than naive LWW. Trap: merge whole snapshots.

(c) Answer: read-your-writes via session token/stickiness. Trap: assuming eventual means immediate.
