Message Passing

Reason about communication when senders and receivers do not share memory or timing.

Rapid exam refresher

  • Format, correlation ID, order, ACK and retry define protocol.
  • RPC blocks, queues decouple.
  • duplicates/reordering normal.
  • exactly-once is not assumed.

Purpose, scope and examiner demand

Message passing lets separate processes exchange requests, replies or events. The core task is to describe delivery, ordering and duplicate handling rather than assuming a call behaves like a local function call.

Exam focus by part

  • Format, correlation ID, order, ACK and retry define protocol.
  • RPC blocks, queues decouple.
  • duplicates/reordering normal.
  • exactly-once is not assumed.

Question-demand diagnosis and answer plan

  1. Identify sender, receiver, message and response.
  2. Say whether the interaction is synchronous request/reply or asynchronous queue/event.
  3. Address delay, loss, duplication and ordering.
  4. Use correlation IDs, acknowledgements, retries or idempotency where needed.

Question-type cues

  • Application cue: Payment command ACK is lost.
  • Analysis cue: Consumer crashes after side effect before ACK.

Definitions, notation and discriminating comparisons

  • Send / receive: transfer a message through a communication channel.
  • Synchronous: caller waits; asynchronous: sender continues after enqueueing.
  • ACK: acknowledgement of receipt, not necessarily completed work.
  • Idempotent: repeating an operation has the same intended effect as doing it once.
  • FIFO ordering: first sent is first received on a stated channel; it is not a global order.

Step-by-step methods and solution routes

Draw two lifelines. Mark the request and reply, then insert the possible failure point. If the reply is lost, the sender cannot know whether the receiver acted. Retrying is sensible only if the receiver can recognise the request ID and safely return the old result or avoid repeating the effect.

Reasoning checkpoints

  1. Use and justify: Format, correlation ID, order, ACK and retry define protocol.
  2. Use and justify: RPC blocks, queues decouple.
  3. Use and justify: duplicates/reordering normal.
  4. Use and justify: exactly-once is not assumed.

Worked examples and method extensions

A client sends “reserve seat 17” with ID R9. The server reserves the seat but its reply is lost. The client retries R9. The server records R9 and replies “already reserved for this request,” rather than reserving a second seat. This gives a practical exactly-once effect at the application level.

Exam-paper-led practice

Practice question 1 [medium/hard]

Scenario and demand: A payment command reaches the bank, which performs the debit, then crashes before ACK; the client retries after an ACK loss. Define the message protocol so the debit happens once. [9 marks]

Question-demand diagnosis and fastest route: Include command ID, sender, amount and correlation ID. The bank durably records the ID and outcome atomically with the debit; duplicates return the stored result. ACKs may be retried and messages reordered, so the client correlates replies by ID and uses a status query after timeout. A queue decouples sender/receiver but does not create exactly-once processing by itself. Trap: “exactly once delivery” cannot be assumed from an ACK.

Practice question 2 [medium/hard]

Scenario and demand: Compare a synchronous RPC with an asynchronous queue for a slow image-processing service. [8 marks]

Question-demand diagnosis and fastest route: RPC blocks the caller awaiting a reply and is simple for immediate validation, but couples availability and can exhaust callers during slowdown. A queue accepts a durable command, lets workers scale/retry and returns a job ID; it needs correlation, idempotence, back-pressure and status handling. Choose queueing for a long task where delayed completion is acceptable. Trap: async messaging still needs ordering/duplicate semantics stated.

Topic-specific traps and diagnosis

  • Claiming ACK means the application action succeeded.
  • Assuming all networks preserve a global order.
  • Retrying non-idempotent actions without duplicate detection.

Exam marking checklist

  • Did I distinguish receipt from completion?
  • Did I name the ambiguous failure case?
  • Did I say how duplicates are controlled?
