Public-Key Protocols

Keep public values, secret exponents and attacker assumptions separate.

Purpose

Diffie–Hellman and ElGamal questions reward a disciplined message flow. Mark every published value, calculate each party's result, then name the discrete-logarithm assumption and the authentication limitation.Exam use: Actors, public values, private values, shared result, assumption and authentication status are all labelled.

What the question asks, and plan

  1. Write shared public parameters: group/modulus p and generator g.
  2. Name each secret exponent and derived public value.
  3. Use modular exponentiation to calculate the shared secret or ciphertext.
  4. Show why both expressions agree, then state an active-attacker caveat.
  5. Question interpretation: For run, label public transmissions and private exponents; for attack or discuss, identify the missing authentication or nonce requirement rather than merely saying discrete logs are hard.

Terms and formulas

  • Discrete logarithm problem: given g,gˣ in a chosen group, recover x; intended hard problem for suitable parameters.
  • Diffie–Hellman: Alice publishes A=gᵃ, Bob publishes B=gᵇ; both obtain s=Bᵃ=Aᵇ=gᵃᵇ mod p.
  • ElGamal public key: y=gˣ mod p; encrypt message m with fresh k: (c₁,c₂)=(gᵏ,m yᵏ) mod p; decrypt with m=c₂(c₁ˣ)⁻¹ mod p.
  • Authentication: assurance of peer identity; unauthenticated DH alone does not provide it.
  • Rapid recall: DH shares g^{ab}; ElGamal sends (g^k, m y^k) and recovers m by dividing by (g^k)^x; unauthenticated DH is vulnerable to man-in-the-middle substitution.

Derivation and method

DH works because exponent multiplication commutes: (gᵃ)ᵇ=gᵃᵇ=(gᵇ)ᵃ. In ElGamal, c₁ˣ=(gᵏ)ˣ=gᵏˣ=yᵏ, so multiplying c₂ by its inverse removes the mask. Write this cancellation rather than only asserting it. Fresh k matters: reusing it can expose relations between messages.Exam workflow: Draw a two-column message flow, calculate powers by squaring, and finish with one sentence tying confidentiality or failure to the precise assumption.

Fully worked simple example

Use p=23,g=5. Alice takes a=6, hence A=5⁶≡8. Bob takes b=15, hence B=5¹⁵≡19. Alice obtains 19⁶≡2 mod 23; Bob obtains 8¹⁵≡2 mod 23. Their shared value is 2. These tiny parameters are only for arithmetic practice.

Medium/hard paper-style synthesis

Use ElGamal with p=23, g=5, private x=6, so y=5^6=8. Encrypt m=7 with k=3: c1=5^3=10 and y^k=8^3=6 mod 23, so c2=7*6=19. Decrypt: c1^x=10^6=6; 6^{-1}=4 mod 23, hence m=19*4=76=7. Reusing k would repeat c1 and relate the masked messages.

Two graded prompts

1. Foundation — 7 marks

For p=23,g=5,a=4,b=3, calculate A, B and the shared secret. Exam bridge: public values (3), both secret computations (3), equality/explanation (1). Check: A=4, B=10, shared secret=18.

2. Exam bridge — 8 marks

Why does ordinary Diffie–Hellman not by itself prevent a man-in-the-middle attack? Give one remedy. Check: attacker can replace public values and negotiate separate secrets; authenticate keys/messages, e.g. signatures/certificates.

Hard paper-style synthesis

Paper-style synthesis: Mallory replaces both DH public values in an unauthenticated exchange. Explain the two resulting secrets. Check: Alice shares g^{am} with Mallory and Bob shares g^{bm} with Mallory; Alice and Bob do not share g^{ab}, so the discrete-log problem was not broken.

Practice question - authenticated key exchange [8 marks]

Inspired by: CS402 2024/25 Q4(c-d), which tests a concrete Diffie-Hellman exchange and ElGamal procedure.

Supplied data and task. In Z61*, g=2, Alice chooses a=5 and Bob b=7. Find their shared key. Then explain, using a named attacker Mallory, why this calculation alone does not authenticate Alice to Bob and give a concrete repair. [8 marks]

Question-demand diagnosis: calculate both public values/shared-secret equality, then analyse an active replacement attack rather than alleging that discrete logs are easy. Fastest route: calculate A=25=32 and B=27=128=6, then raise B to 5 (or A to 7).

Worked answer: Alice receives B=6 and obtains 65=7776=29 mod 61. Bob obtains 327=29 mod 61, so the shared key is 29. If Mallory substitutes M=gm for A and/or B, Alice derives gam with Mallory while Bob derives gbm with Mallory. Mallory can decrypt and re-encrypt traffic between these separate sessions; no discrete logarithm was broken. A repair is for Alice and Bob to sign the transcript (parameters, both public values and identities) with certified long-term signing keys and verify those signatures before accepting the secret.

Topic-specific trap: encryption of the public values does not itself establish identity; the authenticated binding must cover the values actually exchanged.

Common mistakes

  • Publishing an exponent instead of its group power.
  • Using the same exponent/nonce notation for separate parties.
  • Assuming confidentiality automatically authenticates a peer.
  • Reusing ElGamal's ephemeral k.
  • Recovery rule: Never describe a transmitted group element as the secret exponent; write A=g^a (public) and a (private) separately.

Checklist

  • Public versus secret values labelled?
  • All powers reduced mod p?
  • Agreement/cancellation derived?
  • Hardness and authentication limitations stated?
  • Final 60-second audit: Actors, public values, private values, shared result, assumption and authentication status are all labelled.
