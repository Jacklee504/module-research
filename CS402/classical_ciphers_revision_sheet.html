Classical Ciphers

Secure the marks in shifts, affine/Hill arithmetic and short principles answers.

Purpose

Classical ciphers are a dependable calculation-and-explanation cluster: translate letters to residues, state the convention, show modular workings, then interpret the result. They also make the modern security lesson tangible: the algorithm may be public; the key must not be.Exam use: Every symbol row, modular inverse, determinant/gcd test and final plaintext/ciphertext label is visible.

What the question asks, and plan

  1. Write the alphabet/residue convention and modulus (usually n, or 27 if the paper defines a 27-symbol alphabet).
  2. Identify the map: shift, affine, or matrix/Hill; encryption and decryption reverse each other.
  3. Calculate every residue modulo n, converting only at the end.
  4. For a definition question, give the principle, consequence and one example.
  5. Question interpretation: For calculate or decrypt, declare the alphabet convention and modulus before touching the symbols; for explain or assess, separate invertibility from security.

Terms and formulas

  • Caesar/shift: E(x)=x+k mod n; D(y)=y-k mod n.
  • Affine: E(x)=ax+b mod n; it is invertible only if gcd(a,n)=1, and D(y)=a⁻¹(y-b) mod n.
  • Hill: block vector x maps to Kx mod n; decrypt with K⁻¹, which exists iff gcd(det K,n)=1.
  • Kerckhoffs's principle: security should depend on secrecy of the key, not secrecy of the algorithm.
  • Rapid recall: Affine keys require gcd(a,n)=1 and use a^{-1}; Hill keys require gcd(det K,n)=1 and K^{-1}=(det K)^{-1} adj(K) modulo n.

Derivation and method

Decryption must undo encryption. For affine encryption, subtract b, then multiply by the inverse of a: a⁻¹(E(x)-b)=a⁻¹(ax)=x mod n. For a Hill key, find the determinant, check it has a modular inverse, form the adjugate, multiply by that inverse, and reduce every entry modulo n. That invertibility check is a mark-saving first step.Exam workflow: Keep a residue row beside the letter row, reduce after every multiplication, and verify decryption by re-encrypting one block.

Fully worked simple example

Use A=0,…,Z=25 and affine key a=5,b=8. Encrypt H=7: E(7)=5×7+8=43≡17, so H becomes R. Decrypt R=17: 5⁻¹≡21 mod 26; D(17)=21(17-8)=189≡7, giving H. The inverse exists because gcd(5,26)=1.

Medium/hard paper-style synthesis

Use A=0,...,Z=25 and K=[[3,3],[2,5]]. Since det K=9 and 9^{-1}=3 mod 26, K^{-1}=3[[5,-3],[-2,3]]=[[15,17],[20,9]]. Encrypt HI=(7,8)^T: Kx=(45,54)^T=(19,2)^T, so TC. Check: K^{-1}(19,2)^T=(319,398)^T=(7,8)^T, recovering HI. This also proves this key is usable; merely writing det K != 0 would not.

Two graded prompts

1. Foundation — 6 marks

With A=0 and E(x)=7x+3 mod 26, encrypt C and state whether this is a valid affine key. Exam bridge: substitution (2), modular result (2), gcd validity (2). Check: C=2, so 17=P; gcd(7,26)=1.

2. Exam bridge — 8 marks

Explain why publishing a cipher algorithm is compatible with security, then state one weakness of a Caesar cipher. Check: name Kerckhoffs's principle; key secrecy is the assumption; only 26 shifts makes exhaustive search easy.

Hard paper-style synthesis

Paper-style synthesis: with A=0 and E(x)=11x+7 mod 26, decrypt R and decide whether changing b to 8 affects invertibility. Check: 11^{-1}=19, so x=19(17-7)=190=8 mod 26, hence I; b changes the shift but invertibility still depends on gcd(11,26)=1.

Common mistakes

  • Changing A=0/A=1 conventions halfway through.
  • Using an affine multiplier with no inverse.
  • Forgetting to reduce negative residues modulo n.
  • Calling obscurity of an algorithm a security proof.
  • Recovery rule: If a negative residue appears, add a multiple of 26 before translating it back to a letter; do not silently switch A=0 to A=1.

Checklist

  • Convention and modulus stated?
  • Inverse/existence check shown?
  • All workings reduced modulo n?
  • Definition answer includes consequence?
  • Final 60-second audit: Every symbol row, modular inverse, determinant/gcd test and final plaintext/ciphertext label is visible.
