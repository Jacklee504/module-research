Question-demand diagnosis and answer plan

Such questions usually ask for a definition, comparison or a small formal/distributed-systems example. Give the precise definition, apply it to a simple scenario, explain a trade-off, and avoid claiming that a simplified principle is universal.

Question-type cues

  • Application cue: Modernise legacy auth safely.
  • Analysis cue: Urgent patch risks legacy break.

Definitions, notation and discriminating comparisons

  • Z schema: a formal description of state and operations, typically declaring variables, invariants and before/after conditions.
  • ACID: atomicity, consistency, isolation, durability, traditional transaction guarantees.
  • BASE: basically available, soft state, eventual consistency, a looser distributed-data approach.
  • CAP: under a network partition, a distributed system cannot simultaneously guarantee both strong consistency and availability for every request.
  • Kernel / plugin: core privileged system component / extension loaded by a host application.
  • Virtual machine / container: hardware-virtualised OS environment / process-level package sharing host kernel.

Step-by-step methods and solution routes

  1. Identify the level: formal model, data consistency, or operating/deployment mechanism.
  2. For a Z-style operation, state the before-state, input, output, post-state and invariant in plain language before symbols.
  3. For CAP/ACID/BASE, name the failure assumption and user-visible consistency consequence.
  4. For VM/container or kernel/plugin comparisons, distinguish isolation/resource model from packaging/deployment convenience.
  5. Finish with a concrete trade-off and do not mix terms from different layers.

Worked examples and method extensions

Practice

A ticket service has two regions. A network partition occurs just as two users attempt to buy the last seat. Explain the CAP decision and a practical response.

Model answer

During the partition, the service cannot guarantee both that every region returns an immediate response (availability) and that both show one strongly consistent seat count (consistency). For the last seat, choose consistency: route/hold the purchase through an authoritative region or temporarily reject/queue the request, so the seat is not sold twice. The user experience is less available, but correctness matters. An eventually consistent display can still show approximate availability elsewhere, provided final checkout uses the authoritative reservation. CAP applies specifically when partition tolerance is required; it is not simply a rule to “pick two of three” in normal operation.

Common trap

Graded practice and hard extensions

1. Foundation

Contrast ACID and BASE in a payment versus social-feed example.

Answer check: payment normally needs atomic, durable, strongly controlled transactions; a feed may accept temporarily stale replicas for availability/scale. “BASE” does not mean no correctness controls.

2. Exam bridge

Write a short answer comparing containers and virtual machines, then state one security implication of each.

Answer check: containers share host kernel and are lighter; VMs virtualise hardware/guest OS and have stronger isolation boundary in many designs. Both need patching/configuration; containers are not automatically secure.

Hard practice — question demand

Urgent patch risks legacy break.

Plan / choice of method

Model the failure or boundary first, then apply these page-specific concepts in order: Legacy has unknown behaviour/coupling/dependencies.; characterisation tests.; adapter/strangler. Finish by checking the final state against the deadline, security property, consistency contract, or performance requirement.

Worked answer

Safety-net baseline/tests, minimal flag/canary/monitor/rollback then planned refactor with measured debt.

Mark-winning points

Credit requires the complete method sequence, explicit verification of the conclusion, and the limiting assumption/trade-off—not merely the recommended technology.

Common trap

Using formal notation without explaining state, invariant and operation meaning.

Topic-specific traps and diagnosis

  • Presenting CAP as three properties selectable freely without the partition condition.
  • Saying eventual consistency means data is permanently inconsistent.
  • Calling Docker a VM or assuming a container replaces an operating system kernel.
  • Using formal notation without explaining state, invariant and operation meaning.

Exam marking checklist

  • Define the principle accurately and at the right layer.
  • Use one small scenario and a trade-off.
  • State relevant assumptions and a limitation.
  • Keep this material proportionate to its lower-confidence status.
