Repeated formal-specification family

Formal specification is the only family on this page with clear repetition across the newer archive (2021/22 and 2023/24). The papers use a short natural-language system description, then ask for an initial state and one or more operations. The notation matters because it makes the invariant and state change unambiguous.

Practice question - stock state in Z (20 marks)

Inspired by: 2021/22 Question 2 and 2023/24 Question 2.

Scenario. A campus shop carries items. For each carried item it records the number currently in stock. An item cannot have negative stock, and stock is recorded for exactly the carried items.

[ITEM]
CampusStock
  carried : ℙ ITEM
  level   : ITEM ⇸ ℕ
where
  dom level = carried

(a) Explain precisely what the state schema says. [5 marks]

Model answer: carried is a set of items. level is a partial function from an item to a natural number, so any recorded stock level is non-negative and each recorded item has one level. The invariant dom level = carried means that an item has a stock entry if and only if the shop carries it. It rules out both a carried item with no level and a level for an uncarried item.

(b) Give a suitable initial-state operation. [5 marks]

InitCampusStock
  CampusStock'
where
  carried' = ∅
  level'   = ∅

Why it is valid: the domain of the empty function is empty, so dom level' = carried'. A valid initial state must satisfy the invariant; merely declaring empty-looking variables is not enough.

(c) Specify an operation Buy that sells a positive quantity of an item already carried, provided enough stock exists. [10 marks]

Buy
  ΔCampusStock
  item? : ITEM
  qty?  : ℕ1
where
  item? ∈ carried
  qty? ≤ level item?
  carried' = carried
  level' = level ⊕ { item? ↦ (level item? - qty?) }

Model answer: ΔCampusStock states that the operation may change the state. The inputs are an item and positive quantity. The first two predicates are the precondition: the item exists and stock cannot become negative. The carried set is unchanged; function override replaces only the selected item’s stock level. The resulting level remains a natural number and its domain is unchanged, so the invariant is preserved. Error handling is not required unless the question asks for it.

Other background prompts

  • Agile (2023/24): if requirements or data sources keep changing, identify an Agile principle, then give two concrete actions such as short feedback cycles, backlog reprioritisation or stakeholder review. Do not substitute a generic definition of Scrum for the requested strategy.
  • Virtualisation/cloud (2019/20): distinguish Type 1/Type 2 hypervisors or IaaS/PaaS/SaaS by who manages hardware, operating system and application, then match the model to a customer need.
  • CAP/ACID/BASE/plugins (2019/20): revise only if taught again; these have no recent repeat evidence in the local papers.

Final check

  • Does every state operation preserve the invariant?
  • Have I separated preconditions from post-state values?
  • Have I treated background topics as lower-confidence rather than predicting them as a fixed recent slot?
