Learning to rank

LTR learns scores from query-document features and relevance labels.

What the local papers show

Direct evidence is 2025/26 Q4(a,b): training examples, ranking metrics, and neural versus traditional LTR; 2021/22 Q2(c) and 2024/25 Q3(c) ask learning for weights.

Rapid exam refresher

LTR learns scores from query-document features and relevance labels. Pointwise predicts grades, pairwise preferences, listwise rankings. Split by query; assess NDCG/MAP/MRR. Neural rankers learn representations but cost more and are less transparent.

  3. Finish with a topic-specific assumption, limitation or trade-off.

Adapted exam practice - Design a product-search ranker. [15]

(a) [7-9 marks]

(a) Demand: connect data to ranking metric. Quickest route: (q,d,label) -> features -> query split -> NDCG@k. Answer: use assessor/debiased interaction labels and lexical, freshness and quality features; tune on held-out queries and evaluate NDCG@k. Trap: put documents from a query in train and test.

(b) [7-8 marks]

(b) Demand: compare representation, compute and explanation. Quickest route: explicit features versus learned embeddings. Answer: tree/rank-SVM is faster/inspectable; neural LTR captures semantic matching but needs more data, compute and latency control. Trap: neural ranking removes need for labels.
