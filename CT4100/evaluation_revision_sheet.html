CT4100 Topic Guide

Retrieval evaluation

Learn how to decide whether a ranked search system actually helps.

Exam-use protocol

Before writing, identify the command word: calculate/trace requires an ordered derivation; explain requires a definition, mechanism and assumption; compare/design requires matched criteria, a justified choice and a limitation. The topic-specific recall and worked routes below are the material to adapt—not text to copy blindly.

Part-by-part recall: definitions, assumptions and mechanics

Definitions: precision=TP/(TP+FP), recall=TP/(TP+FN); AP averages precision at relevant ranks and MAP averages AP by query. Judgements proxy user relevance and may be incomplete. Compare: precision/recall ignore diversification; NDCG values graded relevance at high rank. Question cue: state objective, cutoff and judgement base before calculating.

Worked practice 1 — paper-style synthesis (recurring-topic pattern; not a quoted paper prompt) precision-recall

Question demand: Relevant results occur at ranks 1,3,4; four relevant exist. Draw points. Plan/choice: update TP down the list. Worked answer: (R,P)=(1/4,1),(1/2,2/3),(3/4,3/4), at relevant ranks. Mark-winning points: recall denominator is all relevant documents; label axes. Common trap: retrieved count as recall denominator.

Worked practice 2 — synthesis / design

Question demand: Evaluate diversified top-10 search. Plan/choice: combine rank relevance with intent coverage. Worked answer: report NDCG@10/P@10 and a subtopic coverage measure against a baseline, using graded pooled judgements and per-intent inspection. Mark-winning points: explain trade-off and uncertainty. Common trap: MAP alone measures first-page experience.

Purpose and module relevance

Evaluation connects an IR design to evidence. CT4100 repeatedly uses precision, recall, average precision, MAP, user effort and diversity.

What a question is really asking

Choose a measure that fits the user task and interpret it. Plan: build the relevance counts; calculate the measure; say what behaviour it rewards; name what it hides.

Prerequisites, vocabulary and notation

  • TP: relevant retrieved; FP: non-relevant retrieved; FN: relevant missed.
  • Precision=TP/(TP+FP); recall=TP/(TP+FN).
  • Average precision averages precision at ranks containing relevant results; MAP averages AP over queries.
  • Diversity: top results should cover different useful aspects.

Method: evaluate a ranked list

  1. State the information need and relevance judgement source.
  2. Mark each returned item relevant or not.
  3. Calculate precision and recall at a named cutoff.
  4. For a ranked measure, record precision whenever a relevant item appears and average it.
  5. Interpret: early precision suits impatient users; recall suits exhaustive tasks; add diversity for ambiguous queries.

Worked practice 3 — foundational calculation

Question

A system returns 5 documents, 3 relevant. There are 6 relevant documents in the collection. Find precision and recall.

Model answer

TP=3 and FP=2, so precision=3/5=0.60. FN=3, so recall=3/6=0.50. The system's first five contain useful material, but it has still missed half of what is known relevant.

Question interpretation and independent practice

Build confidence

When can precision rise while recall falls? Check: returning fewer, highly trusted results can remove false positives but also omit relevant items.

Exam bridge

Design an evaluation for travel search. Outline: query set and judgements; P@k/MAP; task completion or time; diversity across destinations; limitations of offline labels.

High-value traps and corrections

Integrated paper-style practice - evaluate a ranked list [9 marks]

Scenario. Four documents are relevant. At ranks 1 to 8 a system returns R, N, R, N, N, R, N, N. Calculate P@3, recall@6 and AP, then explain why one precision value is insufficient.

Question-demand diagnosis: rank order and the total relevant set require different denominators and a rank-sensitive metric.

Fastest route: count relevant prefixes, then use precision only at ranks 1, 3 and 6 for AP.

Worked answer: P@3=2/3 and recall@6=3/4. Relevant-rank precisions are 1, 2/3 and 3/6, hence AP=(1+2/3+1/2)/4=.542; the unfound fourth document contributes zero. P@3 hides whether later relevant documents are found and whether their order is good, so compare held-out queries with MAP or nDCG as well as recall where comprehensive retrieval matters.

Topic-specific trap: AP divides by the total relevant documents, not the retrieved relevant count.

  • Treating recall as relevant/retrieved rather than relevant/all relevant.
  • Ignoring rank when discussing MAP.
  • Assuming one number represents every user objective.

Final answer checklist

  • Are the numerator and denominator clear?
  • Is the cutoff or ranking position stated?
  • Have I tied the measure to the task?
